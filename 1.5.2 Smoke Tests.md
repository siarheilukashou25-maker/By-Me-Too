# Smoke Test

Documento que explica qué es QA, qué técnicas existen y en qué consiste el smoke test que vamos a realizar, junto con su checklist de ejecución.

---

## 1. ¿Qué es QA?

**QA (Quality Assurance, o Aseguramiento de la Calidad)** es el conjunto de actividades y procesos cuyo objetivo es garantizar que un producto de software cumple los requisitos definidos y funciona de forma correcta, estable y fiable antes de llegar al usuario final.

QA no consiste solo en "buscar errores": también busca **prevenirlos**, mejorando la forma en que se diseña, desarrolla y prueba el software.

## 2. ¿Qué hace un equipo de QA?

- Analizar requisitos y criterios de aceptación.
- Diseñar casos de prueba y planes de pruebas.
- Ejecutar pruebas (manuales y automatizadas).
- Detectar, documentar y reportar defectos (bugs).
- Verificar que los bugs corregidos están realmente resueltos.
- Validar que los cambios nuevos no rompen lo que ya funcionaba (regresión).
- Aportar métricas e información para decidir si una versión está lista para salir.

  ## 3. Técnicas y tipos de pruebas

| Técnica / Tipo | Descripción |
|---|---|
| **Smoke test** | Verificación rápida de las funcionalidades críticas para comprobar que la build es estable. |
| **Sanity test** | Comprobación puntual y acotada tras un cambio o corrección concreta. |
| **Pruebas funcionales** | Validan que cada funcionalidad se comporta según los requisitos. |
| **Pruebas de regresión** | Confirman que los cambios no han roto funcionalidades existentes. |
| **Pruebas de integración** | Comprueban que los distintos módulos o servicios funcionan bien juntos. |
| **Pruebas end-to-end (E2E)** | Recorren flujos completos de usuario de principio a fin. |
| **Pruebas exploratorias** | Se explora la aplicación sin guion fijo, apoyándose en la experiencia del tester. |
| **Pruebas de rendimiento** | Miden velocidad, carga y estabilidad bajo uso intensivo. |
| **Pruebas de seguridad** | Buscan vulnerabilidades y accesos indebidos. |
| **Pruebas de usabilidad** | Evalúan lo fácil e intuitivo que resulta usar el producto. |
| **Pruebas de compatibilidad** | Verifican el funcionamiento en distintos navegadores, dispositivos y sistemas. |
| **Pruebas de aceptación (UAT)** | El cliente o usuario valida que el producto cubre sus necesidades. |

Además, según cómo se ejecutan, las pruebas pueden ser **manuales** (las realiza una persona) o **automatizadas** (las ejecuta un script o herramienta como Junit).

# 4. ¿Qué es un smoke test?

El **smoke test** (o "prueba de humo") es una batería **corta y rápida** de pruebas que comprueba que las funcionalidades más críticas de una aplicación funcionan tras un despliegue o una nueva build.

El nombre viene del hardware: al encender un equipo por primera vez, si no sale humo, se puede seguir probando.

**Características:**

- Es **superficial pero amplio**: cubre lo esencial, no los detalles.
- Es **rápido**: normalmente minutos, no horas.
- Actúa como **filtro de entrada**: si falla, la build se rechaza y no se continúa con pruebas más profundas.
- Se puede ejecutar de forma manual o automatizada.

**Qué NO es:** no sustituye a las pruebas funcionales ni de regresión completas; solo responde a la pregunta *"¿merece la pena seguir probando esta versión?"*
